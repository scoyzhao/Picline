### 怎么使用

1. 正常截图或挂图，无须改变原来的收图方式。
2. 需要 9 张上限时，在菜单栏选择 **保留数量 → 9 张（适合微信）**。该选项不会自动开启，原来的数量设置会保留。
3. 点击菜单栏或任意图片右键菜单中的 **复制全部图片**。
4. 切到微信或 Codex 的输入框、访达文件夹或其他目标软件，按 `Command + V` 粘贴。**微信、Codex 和访达的批量粘贴均已实际验证通过。**

复制按晾衣绳上的原排列顺序进行，不拼成长图、不缩小原图，也不会把图片从绳子上取下。多张使用系统原生文件列表，单张同时提供图片数据；目标软件可能按图片或文件附件接收，具体取决于该软件。

### 全部隔空投送

1. 在任意挂图上右键，选择 **隔空投送全部图片 · N 张**，位于原来的「隔空投送」下方。
2. 在 macOS 的 AirDrop 窗口中，手动选择接收设备。Picline 不预选收件人，也不会自动向附近设备发送。
3. 投送或取消后，原图和晾衣绳上的挂图都保留。

原来的 **隔空投送** 仍只作用于右键的单张或已选中的一组；新增的 **隔空投送全部图片** 始终作用于全部挂图中的图片，也包含屏幕外的图片，跳过录屏和正在取下的项目。

按挂图顺序提交原始文件地址，不拼图、不打包、不重新编码或缩小原图；接收端的实际展示顺序由系统决定。投送本身不额外限制为 9 张，使用更大的挂图上限时也会提交全部图片。

### 使用边界

- 「复制全部图片」跳过录屏和正在移除的项目；没有可复制图片时，菜单项置灰。
- 复制前检查图片是否可读取。源文件丢失或不可读时，提示失败，不先清空原有剪贴板，也不悄悄只复制剩余图片。
- 全部隔空投送没有图片时置灰；提交前以及右键菜单关闭后再次检查源文件。任一图片丢失或无法读取，会提示「隔空投送失败」，不会悄悄只提交剩余图片。系统服务不可用时也会明确提示。
- 打开 AirDrop 窗口不代表投送成功；设备发现、接收确认及传输结果由 macOS 处理，Picline 不提前显示成功提示。
- 数量上限统计晾衣绳上的全部项目，录屏也占一个位置。达到上限的提示适用于所有数量选项，不仅是 9 张。
- 调低上限后，已有数量可能暂时超过上限；原图保留，直到数量低于上限才允许继续挂图。内容去重规则不变。
- 这里只取消「超限自动移除」。手动取下、丢弃或移到废纸篓仍沿用上游规则，应用收件箱里的文件可能被移入废纸篓。
- 本次新增文案提供简体中文和英文，其他语言缺少的新文案回退到英文。

## 这是什么

Picline 是 [Tendedero](https://github.com/alejandrobujan/tendedero) 的一个修改分支。原项目由 Alejandro Buján 编写；**老张** 在它上面强化了收图能力（读第三方截图工具的剪贴板、跨工具去重、指定打开图片的应用），[Picline 上游](https://github.com/Xinguangcuican/Picline) 又修好了多桌面，加了隔空投送、长按预览、访达入口，以及一次选中几张一起用。本分支在保留这些功能的基础上，新增了上面列出的 macOS 定制。

两个平台，同一套交互：

| | macOS | Windows |
| --- | --- | --- |
| 形态 | 菜单栏图标 + 屏幕顶部的绳子 | 托盘图标 + 屏幕顶部的绳子 |
| 安装 | `Picline-0.2.7.dmg`，拖进「应用程序」 | 一个 exe，双击就跑，不用安装 |
| 加选键 | `Command` | `Ctrl` |
| 界面语言 | 11 种，可切换 | 中文 |

# macOS

## 安装

1. 下载 `Picline-0.2.9.dmg`，双击打开，把 `Picline` 拖进「应用程序」。
2. 首次打开会被 Gatekeeper 拦（本版未做公证，属正常现象）。两种放行办法：
   - 系统设置 → 隐私与安全性 → 拉到下面点「仍要打开」，再确认一次；
   - 或终端执行：`xattr -dr com.apple.quarantine /Applications/Picline.app`
3. 启动后菜单栏出现图标。要收截图，先在菜单里勾选「接收剪贴板图片」。

## 收图

- **剪贴板**：截图工具复制的图、浏览器里复制的图、访达里复制的图片文件都能接收，不需要先添加文件夹。菜单里勾选「接收剪贴板图片」才开启。
- **监视文件夹**：菜单栏 →「接收其他文件夹的截图」→「添加文件夹…」，可以是截图工具的保存目录，也可以是它的临时目录；按日期创建的子文件夹也受监视。
- **系统截图**：「接收系统截图」会把 macOS 自带截图工具的输出改到应用自己的文件夹并关掉浮动缩略图，退出或关掉选项时恢复。
- **去重**：按解码后的像素和方向精确匹配，同一张图从目录、剪贴板或多个工具进来只挂一次；裁剪、标注、重压过算不同内容。

## 从访达挂图

选中一张或多张图片，右键 →「打开方式」→「Picline」，图会复制一份进应用并挂到绳上。QSpace 等第三方文件管理器的「打开方式」同样可用，也可以直接把图拖到 Picline 的图标上。

## 从源码构建

### 常规构建

需要 macOS 14+ 和支持 Swift 5.9+ 的开发工具链。保留上游构建与打包方式：

```sh
scripts/build-picline.sh release    # 通用二进制（arm64 + x86_64），产物在 build/Picline.app
scripts/package-dmg.sh              # 打包成 build/Picline-<版本>.dmg
swift test --disable-sandbox        # 完整 XCTest 套件
swift scripts/check-strings.swift   # 检查文案键与本地化
```

### 本机旧工具链兼容构建

本次开发的 Mac 使用 Swift 5.8.1，常规 SwiftPM 构建不可用，因此额外提供直接调用编译器的脚本。

**前提：** 当前 Mac 已安装 `/Applications/Picline.app`，脚本复用它的 `Info.plist` 和图标。该脚本只构建当前 CPU 架构，不生成通用包；不安装或升级开发工具，也不会自动替换正在运行的应用。

```sh
/bin/bash scripts/build-local.sh         # 生成 build/local/Picline.app，完成本地签名检查
/bin/bash scripts/build-local.sh check   # 批量复制与数量上限回归检查，不使用用户剪贴板
/bin/bash scripts/build-local.sh check-airdrop   # 全部隔空投送定向检查，不实际发送
```

兼容代码仅在 `compiler(<5.9)` 时启用，较新的编译器继续使用原生接口。应用标识保持不变，现有设置与挂图记录继续使用。

### 隔离的 AirDrop 界面检查

```sh
/bin/bash scripts/build-local.sh airdrop-preview
open build/local/AirDropCheck.app
```

使用独立应用标识和测试偏好设置，只挂红、绿、蓝 3 张生成的测试图，不读取日常 Picline 的挂图记录或剪贴板，也不替换 `/Applications/Picline.app`。在测试图上右键，可检查单张入口与「隔空投送全部图片 · 3 张」是否同时存在，再检查系统 AirDrop 窗口；不选择接收设备即可取消，测试不会自动发送。

### 提醒预览与检查

先执行上面的定向检查以生成检查程序，再运行以下命令。预览会短暂显示测试提示，但不会发送消息或使用用户剪贴板。

```sh
cp -R Sources/Tendedero/Resources/zh-Hans.lproj build/local/
build/local/check-copy-all --preview-feedback -interfaceLanguage zh-Hans
build/local/check-copy-all --preview-feedback --dark -interfaceLanguage zh-Hans
```

渲染图位于 `build/copy-all-check/feedback-*.png`。`scripts/inspect-pasteboard.swift` 用于手动排查系统剪贴板的文件列表；它会读取并打印剪贴板元数据，日常使用 Picline 不需要运行。

# Windows

> Windows 每改一版，版本号第三位加一；满 9 就进第二位（`0.1.9` 之后是 `0.2.0`），所以永远只有三位、没有 `0.1.13` 这种两位数。这一版接着往下数，是 **0.2.4**：早先那几个两位数的版号（`0.1.10`–`0.1.13`）按同一规则现在是 `0.2.0`–`0.2.3`。

Windows 端另有独立仓库 [`Xinguangcuican/Picline-Windows`](https://github.com/Xinguangcuican/Picline-Windows)，提交历史单独可查；本仓库的 `windows/` 是它的镜像，方便一处看两端。

## 安装

1. 下载 `Picline-0.2.4-win-x64.exe`（绝大多数机器）或 `Picline-0.2.4-win-arm64.exe`（骁龙本等 ARM 机器）。
2. 双击运行。不用安装，也不写注册表 —— 除了下面那条可选的资源管理器右键菜单（一键开关，关掉即删键）。
3. 首次运行会被 SmartScreen 拦一下（未签名）：更多信息 → 仍要运行。

## 怎么把绳子放下来

| 做法 | 结果 | 起始版本 |
| --- | --- | --- |
| 指针停到屏幕最上面 | 立刻放下来（0.09 秒缓冲）；绳子上没有图时不下来 | 0.1.0；空绳不响应自 0.2.0 |
| 按住一个键再贴顶 | 托盘右键 →「贴顶唤出」→ 不需要按键 / `Ctrl` / `Alt` / `Shift`，选择会记住 | 0.1.8 |
| 指针离开绳子 0.5 秒 | 自己收回去 | 0.1.0 |
| `Ctrl + Alt + T` | 显示 / 隐藏，**可自己改**：托盘右键 →「快捷键：…」，按一遍新组合即可（`Esc` 取消、`Delete` 取消设置） | 0.1.0；0.1.9 起可改 |
| `Ctrl + Alt + Shift + Q` | 退出 | 0.1.0 |

## 右键菜单

| 菜单项 | 做什么 | 起始版本 |
| --- | --- | --- |
| 预览 / 复制图片 / 复制为文件 | 复制图片写 `CF_DIB`，在微信里 `Ctrl + V` 直接发图；复制为文件写 `CF_HDROP` | 0.1.3 |
| 存到桌面 / 在资源管理器中显示 / 用默认看图程序打开 | 存一份 png、定位文件、交给默认程序 | 0.1.3 |
| **标记** | 用系统自带的画图打开原文件；保存后卡片跟着更新，打不开画图时会明说 | 0.2.3 |
| 取下这张 / 左边全部 / 右边全部 / 全部取下 | 从绳上取下；选了一组时左右两侧置灰 | 0.1.3；0.1.7 起置灰 |
| **对整组生效** | 选中三张，右键其中任意一张，「存到桌面（3 张）」就是三张一起存 | 0.1.6 |

「复制图片」是例外：剪贴板一次只放得下一张位图，它只复制右键的那一张；要发多张用「复制为文件」或直接拖。

## 从源码构建

源码在 [`windows/`](windows/)，Rust 手写 Win32 + GDI+ 绑定，没有运行时依赖。在 Mac 上用 llvm-mingw 交叉编译出两个架构：

```sh
cd windows
scripts/build-win.sh both     # dist/Picline-<版本>-win-{x64,arm64}.exe
```

## macOS 与 Windows 不一样的地方

两个版本交互对齐，但有些动作天生不同，这里是全部差异，没有隐藏项：

| 事项 | macOS | Windows |
| --- | --- | --- |
| 双击 | 用默认应用或自选应用打开文件 | 全屏预览窗（压暗桌面、放大图片） |
| 快速查看 / 标记 | 有：长按或力触控快速查看，中键标记 | 标记有（右键 →「标记」，用系统画图，存回原文件）；快速查看没有，用双击预览代替 |
| 隔空投送 | 有 | 没有；用「复制图片」粘到聊天窗口，或直接拖 |
| 加选键 | `Command` | `Ctrl` |
| 放下绳子的快捷键 | 可自定义（默认 `⌃⌥T`），菜单栏「快捷键 → 更改快捷键…」 | 可自定义（默认 `Ctrl + Alt + T`），托盘「快捷键：…」，按一遍新组合 |
| 挂图入口 | 访达「打开方式 → Picline」 | 资源管理器右键「挂到 Picline」 |
| 界面语言 | 11 种，可切换 | 中文 |
| 图片格式 | 系统 ImageIO 能解的都能挂（含 webp、heic） | GDI+ 与系统 WIC 能解的都能挂（webp / heic 取决于机器上装没装对应解码器） |
| 虚拟桌面 | 所有 Space 通用 | 切换虚拟桌面时窗口不跟随 |
| 开机自启 | 菜单里勾选 | 托盘菜单里勾选（写 HKCU 的 Run 键） |

## 多桌面是怎么修的

带 `canJoinAllSpaces` 的 `NSPanel` 一旦 `orderOut` 再 `orderFront`，系统可能把它永久绑在某个 Space 上 —— 这是上游 [issue #80](https://github.com/alejandrobujan/tendedero/issues/80) 的症状。解法不是去修那个窗口，而是**发现它不在当前桌面时，直接重建一个新窗口**。全部改动集中在 `Sources/Tendedero/AppDelegate.swift`，共 31 行；之后所有版本都建在这个修法之上。

## 发版

打一个 tag 推上去，编译、打包、发 Release 全部由 GitHub Actions 完成：

```sh
git tag v0.2.9
git push origin v0.2.9
```

1. **版本号取自 tag**，代码里的任何数字都不用改。
2. **发布说明取自 `CHANGELOG.md`** 里对应版本的段落，末尾自动附上安装说明。
3. **macOS 产物自动上传**；Windows 的 exe 体积小、又不需要签名，发版后手动补传一次：

```sh
gh release upload v0.2.8 windows/dist/Picline-0.1.10-win-*.exe \
  windows/dist/Picline-0.2.4-win.zip
```
